# Расписание тренировок: WordPress

Файл `forward-training-schedule.php` одновременно решает две задачи:

1. добавляет защищённую страницу **Инструменты → Импорт тренировок**;
2. публикует read-only API `GET /wp-json/app/v1/get-trainings` для мобильного приложения.

## Установка

1. Создайте каталог `wp-content/mu-plugins`, если его ещё нет.
2. Скопируйте туда `forward-training-schedule.php`.
3. Убедитесь, что активен плагин **The Events Calendar**.
4. Откройте в WordPress **Инструменты → Импорт тренировок**.

MU-плагин загружается автоматически и не зависит от активной темы. Отдельное правило `.htaccess` не требуется.

## Импорт

Поддерживаются JSON и XML. Рекомендуемый рабочий формат — JSON; готовый файл для расписания с изображения находится в `training-schedule-2026-08.json`.

- `year` необязателен. Без него берётся текущий год WordPress.
- `weekday` обязателен: импортер сверяет его с календарной датой.
- `type`: `ice`/`лед`, `ofp`/`ОФП`/`земля` либо `game`/`игра`/`матч`.
- если `title` не задан или пуст, заголовок события формируется как `Лед`, `ОФП` или `Игра`;
- `uid` необязателен. По умолчанию он стабильно формируется из команды, типа и времени начала.
- повторный импорт того же занятия обновляет событие вместо создания дубля;
- `replace_range: true` переносит в корзину ранее импортированные занятия этой команды, которых нет в новом файле внутри `range_from`—`range_to`;
- перед импортом всегда рекомендуется кнопка **Проверить без записи**.

### Ручное добавление в JSON

Над полем JSON находится конструктор одной записи: дата с календарём, тип «Лед»/«ОФП»/«Игра», наименование, время начала и окончания, примечание. Кнопка **Добавить в JSON** вычисляет день недели, проверяет время и добавляет объект в массив `events`.

Если поле JSON пустое, конструктор создаёт новый набор с текущей схемой, временной зоной и командой по умолчанию. Для безопасности `replace_range` в таком наборе выключен. Если JSON уже заполнен, запись добавляется с сохранением остальных параметров, а `range_from`/`range_to` при необходимости расширяются. Выбранный файл при ручном добавлении сбрасывается, чтобы он не заменил отредактированное поле во время импорта. XML через визуальный конструктор не редактируется.

Чтобы заменить старые заголовки «Тренировка — Лёд» и «Тренировка — ОФП», повторно импортируйте исходный набор: стабильные UID приведут к обновлению существующих событий без создания дублей.

Для расписания 3–9 августа 2026 года поле `year` намеренно не указано: в текущем 2026 году даты корректно соответствуют понедельнику–воскресенью. Если этот же файл запустить в другом году, проверка дня недели остановит импорт — тогда следует явно указать нужный `year`.

## Исправление после публикации ботом

После установки актуального `forward-training-schedule.php` откройте импортированное мероприятие в WordPress. Под обычным редактором находится блок **Расписание в мобильном приложении**:

- заголовок мероприятия задаёт название карточки, дата и время берутся из полей The Events Calendar;
- **Тип занятия** задаёт метку «ЛЕД», «ОФП» или «ИГРА»;
- **Примечание в приложении** задаёт строку под названием; **Команда** и **Место** также записываются в мобильный API.

Для занятия **04.10, 10:45–12:00 «Лед», неиграющий состав** выберите «Лед» в этом блоке. Для игры **03.10, 11:45–13:15** исправьте там примечание на «Первенство СПб; Малый д. 66». Нажмите **Обновить** для каждого мероприятия. Если по кнопке «Обновить» меняется только текст в основном редакторе, мобильное приложение продолжит показывать прежние тип и примечание: эти поля API берёт из метаданных мероприятия.

Ручные изменения полей и заголовка сохраняются при повторном импорте от бота. Если нужно снова принять данные бота для отредактированного мероприятия, отметьте **Разрешить Джимми боту заменить ручные правки при следующем импорте** и обновите его. Удаление мероприятия из нового полного расписания при `replace_range` по-прежнему удаляет его из мобильного расписания. Изменения даты и времени бот может внести независимо от ручных правок.

Чтобы проверить результат до открытия приложения, запросите API за 3–4 октября и проверьте поля `type` и `note` нужных `id`. Затем откройте в приложении неделю 28 сентября — 4 октября и потяните экран вниз для обновления. Для такого исправления достаточно обновить MU-плагин на сайте; выпускать новый APK не требуется.

## Проверка API

```powershell
$url = 'https://www.hc-forward.com/wp-json/app/v1/get-trainings?date_from=2026-08-01&date_to=2026-08-31&team=forward-2014'
Invoke-RestMethod -Uri $url | ConvertTo-Json -Depth 8
```

Пустое расписание возвращает HTTP 200, `data: []` и `count: 0`. Это штатный результат, а не ошибка подключения.
