# ХК «Динамо Форвард 2014» — мобильное приложение

Мобильное приложение для просмотра матчей детской хоккейной команды, результатов, турнирных таблиц, состава игроков, архива игр и видеозаписей. Проект написан на React Native с Expo и Expo Router и выпускается для Android и iOS.

- Главный экран с текущими и ближайшими матчами.
- Просмотр списка предстоящих игр.
- Архив матчей по сезонам.
- Турниры, турнирные таблицы и статистика команд.
- Карточка матча: счёт, периоды, команды, арена и видео.
- Список игроков и персональные карточки.
- Страница команды и статистика игр.
- Push-уведомления через Expo Notifications.
- Аналитика AppMetrica.
- Мини-игра Memory; экспериментальный аэрохоккей сохранён в проекте.
- Локальное хранение игроков, фотографий, команд, логотипов, турниров и матчей.

## Работа без интернета

Приложение использует SQLite как основной источник стабильных данных и API только для изменяемой части:

1. При наличии сохранённых данных интерфейс открывается сразу из локального хранилища.
2. При доступной сети данные обновляются в фоне.
3. Успешный ответ API атомарно заменяет соответствующий локальный кэш.
4. При сетевой ошибке последний успешный набор не удаляется.
5. При подтверждённом NetInfo отсутствии интернета пользователь видит одно неблокирующее уведомление внутри safe area главного экрана.
6. Пустой успешный ответ API, включая `count: 0` или `data: []`, означает «матчей нет» и не показывает сетевую ошибку.

Постоянно сохраняются:

- стартовая конфигурация и версии данных;
- текущие и прошедшие турниры;
- команды и локальные логотипы;
- игроки и локальные фотографии;
- списки матчей отдельно для каждого набора фильтров;
- открытые карточки матчей;
- справочники лиг, сезонов и арен.

Первый запуск на полностью чистом устройстве возможен без интернета. В сборку включены SQLite seed-база с командами, аренами, игроками, лигами, сезонами и 949 историческими играми, а также архив доступных фотографий игроков. Текущие и предстоящие матчи, видео и сетевые функции без интернета недоступны, но это не блокирует запуск и просмотр архива.

Исторические игры до 31 июля 2026 года читаются только из SQLite. Завершённые игры начиная с 1 августа 2026 года приложение дозагружает до даты «сегодня минус 7 дней», сохраняет в SQLite и запоминает подтверждённую дату синхронизации. Следующая синхронизация повторяет предыдущий день для безопасного захвата исправлений. Подробности находятся в [docs/LOCAL_DATA_ARCHITECTURE.md](docs/LOCAL_DATA_ARCHITECTURE.md).

## Источники данных

Основной сайт и API принадлежат владельцу приложения и могут дорабатываться совместно с клиентом.

- Базовый API: `https://www.hc-forward.com/wp-json/app/v1`.
- Стартовая конфигурация: `MobileAppConfig.txt` в теме WordPress.
- Матчи: `/get-events`.
- Команды: `/get-team` и связанные методы `apiService`.
- Игроки: `/get-players-full`.
- Турнирные таблицы: `/get-table/{id}`.
- Push-подписки: `/push-subscription`.

Сетевые контракты и преобразование ответов сосредоточены в `services/` и `data/gameData.ts`. При изменении API необходимо сохранять обратную совместимость либо одновременно обновлять типы в `types/`.

Для списочного `/get-events` пустая выборка должна возвращать HTTP `200` и `{ "status": "success", "data": [], "count": 0 }`. Клиент временно поддерживает текущий ответ HTTP `404` с `code: "no_results"`, преобразуя его в пустой список.

## Архитектура

```text
app/                       Экраны и маршруты Expo Router
components/                Переиспользуемые UI-компоненты
contexts/                  Глобальное состояние сети
data/                      Сборка доменных данных приложения
database/                  Схема SQLite, миграции и инициализация
services/                  API, загрузка файлов, кэш и аналитика
types/                     TypeScript-контракты
utils/                     Форматирование и вспомогательная логика
plugins/                   Expo config plugins
assets/                    Иконки, изображения и звуки
docs/                      Baseline и сценарии ручной проверки
```

Ключевые модули:

- `app/_layout.tsx` — запуск приложения, восстановление данных и фоновые задачи.
- `database/index.ts` — подключение bundled seed-базы и применение миграций.
- `database/repository.ts` — единый SQLite repository для справочников и матчей.
- `database/migrations.json` — единый источник схемы для приложения и seed-генератора.
- `assets/database/seed-parts/` и `seed-manifest.json` — версионируемые части стартового снимка.
- `assets/database/forward_seed.db` — автоматически восстановленная перед запуском/сборкой SQLite-база.
- `services/startupApi.ts` — стартовая конфигурация, timeout/retry и fallback.
- `services/referenceDataService.ts` — обновление только изменившихся версионированных справочников.
- `services/historicalSync.ts` — инкрементальное пополнение завершённых матчей.
- `services/appUpdateService.ts` — рекомендуемое и обязательное обновление версии приложения.
- `services/persistentCache.ts` — типизированная оболочка постоянного кэша.
- `services/dataAvailability.ts` — состояние использования сохранённых данных.
- `contexts/NetworkStatusContext.tsx` — подписка на состояние сети.
- `app/index.tsx` — главный экран и единственное safe-area уведомление об отсутствии сети.
- `data/gameData.ts` — матчи, преобразование API и persistent SWR-кэш.
- `services/playerDataService.ts` — игроки, фотографии и атомарное обновление.
- `services/tournamentsApi.ts` — конфигурации и таблицы турниров с fallback.

## Локальная установка

Требования:

- Node.js не ниже `20.19`;
- npm;
- учётная запись Expo/EAS;
- для подписанных iOS-сборок — активная Apple Developer Program.

```bash
git switch stabilization/foundation
git pull --ff-only origin stabilization/foundation
npm ci
npm run check
```

Пересоздание и проверка seed-базы из текущего API:

```bash
npm run seed:generate
npm run seed:verify
```

Пересоздание встроенного архива фотографий игроков:

```bash
npm run photos:generate
```

Seed-база хранится в Git частями. Исходные фото хранятся в `assets/player-photos/source/`; `npm ci` автоматически генерирует явный Metro-манифест, и изображения напрямую попадают в приложение без ZIP.

По умолчанию загружаются матчи с `2023-01-01` по `2026-08-07`. Диапазон можно изменить:

```bash
npm run seed:generate -- --from 2023-01-01 --to 2026-08-07
```

Запуск Metro:

```bash
npx expo start
```

## EAS Build

`eas.json` содержит профили:

- `development` — development client;
- `preview` — APK и iOS Ad Hoc для физических устройств;
- `internal` — внутренняя сборка;
- `production` — App Store/Google Play.

EAS CLI не установлен в зависимостях проекта. Для воспроизводимой preview-сборки используется закреплённая версия 21.7.0:

```bash
npm run eas-build -- --platform android --profile preview
npm run eas-build -- --platform ios --profile preview
```

Для iOS Ad Hoc устройство предварительно регистрируется командой:

```bash
npx --yes eas-cli@21.7.0 device:create
```

## Секреты и конфигурация

- `google-services.json` не хранится в Git.
- Для Android EAS получает его через файловую переменную `GOOGLE_SERVICES_JSON` окружения `preview`.
- Apple и Android signing credentials хранятся на серверах Expo.
- Приватные ключи, `.p8`, `.p12`, keystore и provisioning profile исключены через `.gitignore`.
- Секретные значения нельзя добавлять в `app.config.js`, исходный код или README.

## Известные ограничения

- Видеопотоки и внешние страницы требуют сети, даже если карточка матча доступна офлайн.
- Фоновая актуализация ограничена правилами iOS/Android; гарантированное обновление выполняется при активном приложении.
- Часть старых сервисов пока содержит совместимые legacy-методы; их удаление запланировано после стабилизации пользовательских сценариев.
