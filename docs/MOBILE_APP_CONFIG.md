# MobileAppConfig.txt

Статический JSON формируется WordPress-файлом `admin-startup-config.php`. Клиент сохраняет последний успешный конфиг в кэше и имеет его стартовую копию в SQLite, поэтому ошибка сети не блокирует запуск.

## Версии данных

- `config_schema_version` — версия структуры JSON.
- `config_revision` — увеличивается при каждом сохранении формы.
- `data_versions.teams`, `players`, `venues`, `leagues`, `seasons`, `tournaments` — независимые версии наборов.
- Плоские `*_version` сохраняются для обратной совместимости.

Версию набора следует увеличивать только после того, как соответствующий API уже отдаёт новый полный набор. Любое отличие от локальной версии запускает обновление, поэтому уменьшать номера без необходимости нельзя.

## Версия приложения

`app.latest_version` — актуальная опубликованная semantic version. Если установленная версия ниже, клиент показывает рекомендацию обновиться. `app.minimum_supported_version` — минимально допустимая версия; ниже неё уведомление обязательное и не закрывается.

Значения задаются отдельно для iOS и Android. `app_store_url`, `google_play_url` и `android_download_url` определяют действие кнопки обновления.

## Синхронизация

- `historical_start_date` — начало пополняемого архива, сейчас `2026-08-01`.
- `historical_delay_days` — безопасная задержка перед архивацией завершённых игр.
- `event_chunk_days` — максимальный размер одного диапазона.
- `player_photo_archive_url_template` — URL ZIP, содержащий `{version}`.

## Резерв для развития

Конфигурация уже содержит независимые feature flags, режим технических работ, одноразовое объявление, базовый URL и таймаут API. Неизвестные поля клиент игнорирует, поэтому сервер может добавлять новые необязательные поля без смены `config_schema_version`. Версию схемы нужно повышать только при несовместимом изменении существующего контракта.

## Установка PHP-файла

1. Сделать резервную копию действующего файла.
2. Заменить `admin-startup-config.php` обновлённой версией.
3. Открыть в WordPress раздел «Старт. конфигурация».
4. Проверить версии данных и адреса магазинов; сохранить форму.
5. Открыть сформированный `MobileAppConfig.txt` и убедиться, что JSON содержит `status: "success"`, `config_schema_version: 2` и `data_versions`.
6. Если менялась версия игроков, проверить наличие `player_photos_v<version>.zip`.

Первое сохранение автоматически наследует версии арен, лиг, сезонов и турниров из прежней `teams_version`, если отдельных значений раньше не существовало.
