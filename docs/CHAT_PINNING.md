# Закреплённые сообщения

Серверные закрепления общие для комнаты; право изменения равно праву писать.
Клиентская верхняя полоска не связана с «Избранным». Контекстное меню предлагает
«Закрепить сообщение» либо «Открепить сообщение». Системные, удалённые и ещё
неотправленные сообщения закреплять нельзя.

Сообщения идут от старых к новым по created_at самого сообщения. Время закрепления
и редактирования не влияет на порядок; bigint sequence используется только для
стабильного порядка при одинаковом времени, без потери точности.
Тап открывает показанное сообщение и переключает полоску к следующему более старому,
после самого старого — к самому новому. Утолщённый сегмент всегда отмечает превью
в полоске, а не сообщение в ленте. Для трёх закреплений по возрастанию created_at:
вход — превью №3 и нижний сегмент; тап — фокус №3, превью №2 и средний сегмент;
затем фокус №2, превью №1 и верхний сегмент; затем фокус №1, превью №3 и нижний сегмент.
До подтверждения перехода, при ошибке или отмене превью/сегмент не меняются.
Переход подгружает контекст старого сообщения и снимает фильтр автора; стандартная
подсветка и возврат к последним сообщениям сохранены. Первая строка очищается от
служебных маркеров форматирования; для медиа без подписи показывается тип вложения.

Список перечитывается при входе/возврате, подключении, событиях закрепления,
изменениях закреплённых сообщений, а также раз в 30 секунд в активном приложении.
События не меняют выбор другого пользователя. Старый сервер (404) не ломает чат;
возможность закрепить появится после обновления сервера. При потере сети остаётся
последний известный список; при отказе в доступе он очищается.

Проверка: `node --no-warnings --experimental-strip-types checks/messenger-pins.mjs`.
На устройствах проверить один/несколько/старые закрепления, фильтр автора,
повторный вход, два пользователя, чтение без записи, удаление и восстановление
сети. Нативная обработка клавиатуры/Android-отступы не изменяются.

## Исправление видимости меню

Запрос списка выполняется с приоритетом normal: он не является отменяемой
фоновой предзагрузкой. До первого ответа видимость пункта определяется уже
известным can_write комнаты; явный отказ can_pin/401/403/404/405 имеет приоритет.
При временной ошибке выполняются короткие повторы (1, 2, 5 с) и сохраняются
последние данные, вместо маскировки сбоя под отсутствие права. Открытие
контекстного меню повторяет запрос. Каждый PUT/DELETE по-прежнему проверяется
сервером. Обработка клавиатуры не меняется.

Проверка фактического React hook и транспортного планировщика:
`PIN_TEST_MODULES=/tmp/forward-pin-tests node checks/messenger-pins-runtime.cjs`.
В указанную папку устанавливаются только для тестов react@19.1.0 и
react-test-renderer@19.1.0; зависимости приложения не изменяются.

## Полоса закрепления

При входе/повторном открытии чата и при ручной прокрутке к действительному концу
ленты выбирается последнее (самое новое по created_at) закреплённое сообщение.
Низ страницы старой истории и программный переход к закреплению выбор не сбрасывают.
После самого старого сообщения цикл переходит к самому новому. Счётчик визуально не выводится:
заголовок всегда «Закрепленное сообщение», а ниже — начало первой строки или Фото/Видео.
Слева от текста, после сегментов — квадратная миниатюра первого фото/видео вложения,
справа — значок строк с булавкой (часть той же кнопки перехода, не отдельное действие).
Кадр видео извлекается в момент 0 с, без воспроизведения и звука, средствами уже
установленного expo-video; плеер освобождается по завершении, ошибке или выходе.
На недоступном вложении остаётся значок типа. Новых native-зависимостей нет.

## Подтверждение перехода

Сегменты имеют постоянные ключи ID сообщений. Превью и соответствующий ему жирный
сегмент переключаются лишь после появления целевого сообщения в видимой области
FlatList, а не сразу после команды прокрутки. Неизмеренная строка повторяется,
ошибка/ручная прокрутка/смена комнаты отменяют старый запрос без изменения сегмента.
Для навигации проверяется полностью видимая короткая строка или половина экрана
для высокой строки; прежние правила прочтения сообщений не меняются.
Подгрузка медиа не запускает конкурирующие анимации. Подсветка временная,
но якорь сохраняется до нового действия пользователя.

## Ошибка перехода не является ошибкой синхронизации

Ошибки открытия сообщения отображаются отдельным закрываемым уведомлением.
Переход не устанавливает и не очищает syncError: настоящие ошибки синхронизации
сохраняются до исправления соответствующим механизмом обмена данными.

Подтверждение фокуса использует measureInWindow нативной строки и контейнера
ленты, а не только onViewableItemsChanged. У измерения есть ограничение времени;
свежая viewability используется лишь при отсутствии измерения. Фактически
невидимое сообщение не считается открытым. Индекс берётся из данных FlatList
после commit, с учётом скрытых удалённых сообщений в Избранном и фильтра автора.
При задержке рендера запрос повторяется, устаревший retry отменяется. Автоподгрузка
границ и maintainVisibleContentPosition не конкурируют с явным переходом.

Локальные диагностические события message.navigation.started / focused /
focus_timeout / failed содержат ID цели, платформу, число попыток и геометрию,
без текста сообщения, медиа, токенов и отправки этих данных в AppMetrica.
Ручная прокрутка и выход отменяют ожидание без сообщения об ошибке.
Проверка реальных callback-функций экрана с подменёнными native/SQLite/network:
`npm run check:messenger-navigation`. Реальное устройство отдельно не проверено.

## iOS SDK 54: безопасный аргумент видеоминиатюры

Для первого кадра передаётся `generateThumbnailsAsync([0], options)`, не число `0`.
Типы expo-video разрешают оба варианта, но нативное преобразование числа в массив
в expo-modules-core SDK 54 вызывает iOS-сбой (expo/expo#43372, исправление #42694
в SDK 55). Ошибка может возникать при входе в чат до первого нажатия на закрепление.
Извлечение кадра не отключено. Навигация/измерения, Android-отступы, API и БД
не изменяются. Обновление Expo SDK не требуется. Проверка формы аргумента,
освобождения плеера и отмены: `npm run check:messenger-pin-thumbnail`.
Тесты с подменой моста не заменяют проверку реальной iOS-библиотеки; для неё
есть изолированный simulator harness `checks/ios-pin-thumbnail-smoke.py`.
