# Smoke-тесты стабилизационной ветки

Тесты выполняются на Android и iOS после `npm ci`, `npm run check` и preview-сборки.

Перед сборкой также выполняется `npm run seed:verify`. Ожидаемый `integrity_check`: `ok`.

## 1. Первый запуск с интернетом

- Удалить приложение и установить заново.
- Запустить при стабильной сети.
- Убедиться, что загрузились команды, игроки, турниры и матчи.
- Закрыть приложение штатно.

Ожидание: запуск завершается, офлайн-уведомление отсутствует, данные сохранены. Успешный ответ API с нулём игр не показывает предупреждений.

## 2. Первый запуск без интернета

- Установить приложение на чистое устройство.
- Отключить Wi-Fi и мобильные данные.
- Запустить приложение.

Ожидание: приложение запускается из встроенной SQLite-базы; доступны справочники, игроки, фото и исторические матчи. Видно одно уведомление об отсутствии сети ниже safe area. Текущие и предстоящие игры могут быть пустыми.

## 3. Повторный запуск без интернета

- Сначала успешно выполнить сценарий 1.
- Полностью закрыть приложение.
- Отключить сеть и открыть приложение снова.

Ожидание: приложение открывается с последним успешным набором; на главном экране видно одно офлайн-уведомление ниже safe area. Оно не перекрывает Dynamic Island.

## 4. Потеря сети во время работы

- Открыть приложение онлайн.
- Отключить сеть и обновить главный экран жестом pull-to-refresh.

Ожидание: текущие данные не исчезают и не превращаются в пустые списки; появляется одно уведомление.

## 5. Восстановление сети

- После сценария 4 включить сеть.
- Выполнить pull-to-refresh.

Ожидание: данные обновляются; после успешного ответа предупреждение исчезает.

## 6. Главный экран и ближайшие матчи

- Проверить текущие матчи, ближайшие игры, количество игроков и турниров.
- Сравнить данные с API/сайтом.

Ожидание: корректные даты, команды, счёт и количество элементов; настоящий пустой ответ показывается как отсутствие матчей.

## 7. Карточка матча и видео

- Открыть матч онлайн, затем повторно открыть его офлайн.
- Проверить счёт, периоды, команды и арену.

Ожидание: данные ранее открытого матча доступны офлайн; видео без сети может быть недоступно и не должно ломать карточку.

## 8. Архив, сезоны и турниры

- Открыть архив, сезон, список турниров и таблицу турнира онлайн.
- Повторить после перезапуска без сети.

Ожидание: исторические игры, сезоны и команды читаются из SQLite. Сетевые турнирные таблицы используют последний успешный кэш.

## 9. Игроки и Memory

- Открыть список игроков и несколько карточек.
- Запустить Memory и завершить уровень.
- Повторить без сети.

Ожидание: локальные игроки, фотографии и Memory работают; рекорды сохраняются.

## 10. Версионное обновление справочников

- Не меняя версии в `MobileAppConfig.txt`, перезапустить приложение онлайн и проверить логи.
- Затем увеличить только одну версию, например `venues_version`, и перезапустить.

Ожидание: в первом случае справочники не запрашиваются из API. Во втором загружаются и атомарно заменяются только арены, после чего новая версия записана в SQLite.

## 11. Версионное обновление турнирных таблиц

- Запустить приложение дважды с неизменным `tournaments_version`.
- Проверить логи второго запуска.
- Увеличить `tournaments_version` и запустить ещё раз.
- Открыть турнирную таблицу без сети после успешного обновления.

Ожидание: при неизменной версии видно сообщение `SQLite актуален`, запросы `/get-table/*` отсутствуют. После изменения версии загружаются только отсутствующие или устаревшие таблицы, а затем новая версия фиксируется в SQLite. Офлайн отображается последний успешный набор.

## 12. Инкрементальный архив

- Проверить значение `historical_events_through` в базе.
- Запустить приложение онлайн и дождаться фоновой синхронизации.
- Перезапустить приложение и проверить начальную дату следующего запроса.

Ожидание: курсор двигается только после успешной порции; следующий диапазон начинается на один день раньше курсора; матчи не дублируются благодаря UPSERT по ID.

## 13. Push-уведомления

- Проверить включение и отключение push при наличии сети.
- Запустить приложение офлайн с ранее выбранной настройкой.

Ожидание: сетевой сбой проверки подписки не блокирует запуск и не удаляет локальные данные.

## 14. Медленный или зависший сервер при повторном запуске

- Сначала выполнить успешный онлайн-запуск, чтобы сохранить конфигурацию и снимок предстоящих матчей.
- Ограничить сеть на устройстве либо временно задержать ответы `MobileAppConfig.txt` и `/get-events` более чем на 12 секунд.
- Полностью закрыть и снова открыть приложение, наблюдая логи Expo.
- После открытия интерфейса восстановить нормальную скорость сети и дождаться завершения фонового запроса.

Ожидание: конфигурация и матчи восстанавливаются локально; каждое сетевое ожидание удерживает инициализацию не более 750 мс. Приложение открывается до появления фонового timeout. Медленный сервер при подтверждённом подключении не показывает сообщение «Нет подключения к интернету». После успешного позднего ответа видны логи `[Главный экран] Получен обновлённый фоновый снимок` и/или `[Экран матчей]`, а интерфейс обновляется без перезапуска. Предзагрузка турнира начинается после завершения основного запроса `/get-events`, а не параллельно с ним.

## 15. Импорт расписания тренировок

- Установить MU-плагин по `server/wordpress/README-TRAININGS-RU.md`.
- Открыть **Инструменты → Импорт тренировок** и загрузить `training-schedule-2026-08.json`.
- Сначала выполнить предварительную проверку, затем импорт.
- Повторить импорт того же файла.
- Очистить JSON-поле, вручную добавить через конструктор занятия типов «Лед», «ОФП» и «Игра».
- Добавить ещё одну запись в уже заполненный JSON и проверить расширение `range_from`/`range_to`.
- Изменить день недели одной строки на неверный и повторить предварительную проверку.

Ожидание: текущий год определяется как 2026; первый импорт создаёт 11 занятий, повторный предлагает обновить те же 11 без дублей и меняет стандартные заголовки на «Лед»/«ОФП». Конструктор вычисляет день недели и формирует валидный JSON; новый набор получает `replace_range: false`. Неверный день недели останавливает весь импорт до записи. Пустое воскресенье не создаёт событие; при `replace_range` прежние импортированные занятия, отсутствующие в файле 3–9 августа, переносятся в корзину.

## 16. Экран тренировок и офлайн-режим

- Запустить приложение онлайн и открыть на главном экране «Тренировки».
- Сверить лед/ОФП/игры, даты и время с WordPress.
- Создать занятие, охватывающее текущее время: карточка должна быть серой слева пропорционально прошедшему времени; после окончания серым становится весь фон.
- Убедиться, что вчерашние занятия по умолчанию скрыты; нажать контурную иконку часов в заголовке.
- Проверить появление прошедших занятий только с понедельника текущей недели; нажать заполненную иконку повторно.
- Закрыть приложение, отключить сеть и снова открыть расписание.
- Вернуть сеть и выполнить pull-to-refresh.

Ожидание: первый экран появляется из SQLite; после успешного API-ответа обновляется автоматически. Будущая карточка остаётся белой, текущая заполняется серым слева направо, завершённая полностью серая; прогресс обновляется без перезапуска экрана. Сегодняшние и будущие занятия видны сразу, вчерашние скрыты. Переключатель добавляет прошедшие занятия текущей недели, но не предыдущей, а повторное нажатие возвращает исходный фильтр. Офлайн показывается один блок о сохранённых данных. Успешный ответ `data: []` показывает нейтральное «Расписание пока не опубликовано», а не ошибку интернета.

## 17. Напоминания о тренировках

- В preview/development-сборке открыть настройки.
- Включить «Уведомления о тренировках» и разрешить уведомления ОС.
- Последовательно выбрать 15 минут и 1 час.
- Проверить логи о количестве перепланированных напоминаний.
- Отключить тренировочные уведомления, оставив уведомления о матчах включёнными.
- Для оперативного теста импортировать занятие через 20–30 минут и выбрать 15 минут.

Ожидание: интервалы сохраняются после перезапуска; локальное напоминание приходит в выбранный момент и открывает `/trainings`. Отключение отменяет только тренировочные задачи и не удаляет серверную подписку на матчи. При запрете разрешения ОС переключатель остаётся выключенным с понятной ошибкой.

## 18. Мобильные игры «Заливка льда» и «Х - О, 5 в ряд»

- Отключить сеть и открыть обе игры из раздела «Мобильные игры».
- В «Заливке льда» проверить удержание и отпускание кнопки движения, поворот в обе стороны, рычаг вперёд/назад, задние колёса и автоматическую бортовую щётку.
- Проехать вдоль борта и через скруглённый угол: скорость должна снижаться только при полном прижатии, передние колёса не должны блокироваться полностью.
- Довести покрытие до 99%, дождаться открытия ворот и вернуться через них; до достижения порога ворота должны оставаться закрытыми.
- В «Х - О, 5 в ряд» проверить уровни компьютера 1–5, локальный режим двух игроков, сохранение имён, перемещение и масштабирование бесконечного поля.
- Завершить партии горизонтальной, вертикальной и обеими диагональными линиями.

Ожидание: обе игры полностью работают без сети. Кнопка движения Zamboni активна только во время касания; после завершения заливки отображается корректный результат. Компьютер в «Х - О, 5 в ряд» делает только допустимые локально рассчитанные ходы, блокирует непосредственную угрозу на уровнях 2–5, а победное окно не повторяет текст правила. После 10 минут игры устройство не демонстрирует прежнего выраженного нагрева.

## 19. Нативный редактор и системное «Поделиться»

- Выполнить сценарий только в новой development/preview/production-сборке, не в Expo Go.
- В личном и групповом чате выделить части текста и последовательно применить
  жирный, курсив, подчёркивание и зачёркивание через системное меню.
- Вставить из буфера обычный текст, затем отдельно скопированные изображение и
  файл; убедиться, что текст попал в редактор, а медиа/файл — во вложения.
- Из «Фото», браузера и приложения «Файлы» вызвать системное «Поделиться» и
  выбрать «ХК Форвард 14»; повторить с несколькими изображениями.
- Найти существующий личный/групповой чат, выбрать его и отправить материал.
- Повторить с пользователем без существующего личного чата.
- Во время передачи большого файла нажать системную кнопку «Назад» и затем
  дождаться результата; отдельно проверить сетевую ошибку и повторную отправку.
- Выйти из мессенджера, снова поделиться материалом, войти и завершить отправку.

Ожидание: формат виден уже в поле и сохраняется в пузыре; состояние стиля не
переходит самопроизвольно на новый текст. В системном списке присутствует
приложение, экран показывает только разрешённых получателей и не закрывается во
время подготовки/передачи. Успешное сообщение появляется у адресата один раз;
при ошибке материал и выбранный получатель не теряются. Android возвращается к
приложению-источнику, iOS — к списку чатов «ХК Форвард 14».
