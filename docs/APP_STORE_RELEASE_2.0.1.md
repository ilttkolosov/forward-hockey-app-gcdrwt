## 5. App Privacy

В App Privacy выбрать `Yes, we collect data from this app`. Закрытый характер
мессенджера не отменяет декларирование данных. Apple отдельно требует
декларировать приватные сообщения, фотографии и видео, если они передаются на
сервер.

Рекомендуемая консервативная матрица:

| Data Type | Purpose | Linked to User | Tracking |
| --- | --- | --- | --- |
| Name | App Functionality | Yes | No |
| Email Address | App Functionality | Yes | No |
| Precise Location | App Functionality | Yes | No |
| Emails or Text Messages | App Functionality | Yes | No |
| Photos or Videos | App Functionality | Yes | No |
| Other User Content | App Functionality | Yes | No |
| Search History | App Functionality | Yes | No |
| User ID | App Functionality | Yes | No |
| Device ID | App Functionality, Analytics | Yes | No |
| Product Interaction | Analytics | No | No |
| Crash Data | Analytics, App Functionality | No | No |
| Performance Data | Analytics, App Functionality | No | No |
| Other Diagnostic Data | Analytics, App Functionality | No | No |

Пояснения:

- Precise Location передаётся только по явному действию пользователя при
  отправке геопозиции в чат.
- Other User Content включает файлы, аватары, подписи к вложениям и текст
  жалобы.
- Device ID включает PUSH-регистрацию, связанную с учётной записью, и
  технический идентификатор аналитики.
- AppMetrica не получает тексты сообщений, запросы поиска, логины, имена,
  внутренние ID, PUSH-токены или координаты; отслеживание для рекламы не
  используется.
- Gameplay Content не декларируется, пока игровые результаты остаются только
  на устройстве и не передаются на сервер или стороннему SDK.
- Contacts не выбирать: приложение показывает собственный командный справочник
  и не читает адресную книгу телефона.
- Audio Data не выбирать, пока приложение не записывает и не загружает
  голосовые сообщения или отдельные аудиофайлы как специальную функцию.

Если production Nginx сохраняет IP-адреса в долговременных access-логах,
необходимо дополнительно либо:

1. задекларировать `Coarse Location` для App Functionality/Security без
   tracking; либо
2. настроить фактическую анонимизацию и ограниченный срок хранения до
   публикации privacy label.

## 12. Production build и загрузка

```bash
npx --yes eas-cli@21.7.0 login
npx --yes eas-cli@21.7.0 whoami
npx --yes eas-cli@21.7.0 build:version:get --platform ios --profile production
npx --yes eas-cli@21.7.0 build --platform ios --profile production --wait
npx --yes eas-cli@21.7.0 submit --platform ios --profile production --latest --wait
```

Перед сборкой `build:version:get` должен показать удалённый номер не ниже
последнего загруженного в App Store Connect. Если удалённое значение отстаёт,
выполнить интерактивную синхронизацию:

```bash
npx --yes eas-cli@21.7.0 build:version:set --platform ios --profile production
```

Ввести последний уже использованный build number. Следующая production-сборка
увеличит его автоматически.

`eas submit` загружает бинарный файл в App Store Connect/TestFlight, но не
нажимает финальную кнопку отправки версии на App Review.

## 14. App Store Connect: финальная последовательность

1. Открыть `My Apps → ХК Форвард 14`.
2. В `App Information` проверить категории, Content Rights, возрастной рейтинг
   и DSA status.
3. В `App Privacy` обновить privacy URL и все Data Types, затем нажать
   `Publish`.
4. Создать новую iOS-версию `2.0.1`.
5. Вставить Promotional Text, Description, Keywords, Support URL, Marketing
   URL и текст «Что нового».
6. Загрузить актуальные iPhone-скриншоты. Поскольку приложение поддерживает
   iPad, добавить требуемый App Store Connect набор iPad-скриншотов.
7. Скриншоты должны показывать реальный интерфейс: главный экран, расписание,
   матч/турнир, список чатов, групповой чат с медиа, поиск/реакции,
   безопасность и мини-игры. Не использовать реальные данные детей и личную
   переписку.
8. Дождаться обработки production build и выбрать именно сборку с marketing
   version `2.0.1`.
9. Проверить Export Compliance.
10. Заполнить App Review Information, основной логин/пароль и Notes.
11. Выбрать `Manually release this version`, чтобы после одобрения сначала
    проверить статус и самостоятельно опубликовать релиз.
12. Нажать `Add for Review`.
13. Открыть созданный Draft Submission и нажать `Submit for Review`.
14. Следить за сообщениями в `App Review`; отвечать в том же диалоге и не
    деактивировать review accounts до публикации версии.

## 15. Финальные стоп-факторы

Не отправлять версию на ревью, если выполняется хотя бы одно условие:

- privacy/support URL не опубликован или не содержит контакта;
- основной или второй review account не входит по обычному паролю;
- для входа нужен истекающий invite token;
- сервер, медиа или PUSH нестабильны;
- жалоба, блокировка либо удаление аккаунта не работает;
- в privacy label не добавлены сообщения, фото/видео и User ID;
- скриншоты или тестовые чаты содержат реальные персональные данные детей;
- нет подтверждения прав на используемые фотографии, логотипы или видео.
