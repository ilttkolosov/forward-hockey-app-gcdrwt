# Зафиксированные решения

Дата фиксации: 9 августа 2026 года.

## M-001. Личные сообщения отключены в первой версии

Статус: принято.

Первая версия поддерживает только управляемые групповые чаты. Это сокращает поверхность модерации, исключает неконтролируемое общение взрослых с несовершеннолетними и позволяет сначала проверить ролевую модель.

Схема данных допускает тип комнаты `direct`, но сервер не создаёт такие комнаты, API не публикует соответствующий маршрут, а клиент не показывает интерфейс личной переписки. Включение личных сообщений потребует отдельного продуктового и безопасностного решения.

## M-002. Сквозное шифрование не используется в первой версии

Статус: принято.

Передача защищается TLS, серверное хранилище и резервные копии шифруются инфраструктурными средствами. Сервер может выполнять синхронизацию, модерацию, поиск нарушений и формирование push-уведомлений.

Интерфейс и документация не должны называть переписку «сквозно зашифрованной». Возможное E2EE в будущем проектируется отдельно, поскольку оно меняет восстановление истории, модерацию, поиск и работу с несколькими устройствами.

## M-003. Администратор не читает закрытые чаты скрыто

Статус: принято.

Роль администратора даёт управление пользователями, ролями, шаблонами комнат и жалобами, но не означает автоматическое членство во всех чатах. Для просмотра содержимого в рамках модерации требуется явный ограниченный доступ с причиной, сроком и записью в `audit_log`.

## M-004. Повышенные роли являются дополнительными

Статус: принято.

- Капитан и ассистент остаются игроками и получают дополнительные права в своей команде и сезоне.
- Член родительского комитета остаётся родителем и получает дополнительные права.
- Один пользователь может иметь несколько ролей в разных командах или сезонах.
- Права приглашений выдаются по схеме из [RBAC_MATRIX.md](RBAC_MATRIX.md), а не следуют автоматически из названия роли.

## M-005. Мессенджер отделён от WordPress

Статус: принято.

Мессенджер разворачивается отдельным сервисом на Linux-сервере и использует собственную PostgreSQL-БД. Между БД WordPress и мессенджера нет общих таблиц, прямых SQL-запросов и общих сессий.

Мобильное приложение обращается к двум независимым источникам:

- WordPress API — матчи, команды, игроки, турниры и тренировки;
- Messenger API — учётные записи, роли, приглашения, чаты, сообщения и медиа.

Если в будущем потребуется перенос справочников команды, он выполняется отдельным версионированным импортом через API, а не связью между базами.

## Решения, которые необходимо закрыть до публичного запуска

Они не блокируют создание серверного каркаса:

1. Основной идентификатор входа и восстановления доступа: электронная почта, телефон либо оба варианта.
2. Максимальный размер фотографии и видео, длительность видео и общий лимит хранилища.
3. Срок хранения удалённых сообщений, исходных медиа, аудита и резервных копий.
4. Текст пользовательского соглашения, политики конфиденциальности и порядок согласия для несовершеннолетних.
