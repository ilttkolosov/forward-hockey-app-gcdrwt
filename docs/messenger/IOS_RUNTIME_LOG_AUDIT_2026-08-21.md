# Аудит журнала мессенджера на iOS — 21.08.2026

## Объём наблюдения

Проанализирован один журнал запуска Release-сборки на физическом iPhone. Фрагмент охватывает запуск приложения, вход в мессенджер, открытие двух комнат, переходы приложения между foreground/background, получение четырёх сообщений и обработку PUSH.

Журнал позволяет доказать повторяемость запросов и измерить задержки, но не заменяет Instruments-профилирование CPU, памяти и FPS.

## Краткий итог

- Фатальных ошибок, React Native exception и аварийного завершения нет.
- Локальная лента SQLite открывается быстро: первый экран сообщений готов за 5–6 мс, полная подготовка кэша — за 19–41 мс.
- Переход от нажатия до фокуса комнаты занимает 50–58 мс; позиционирование ленты завершается за 148–283 мс.
- Основной источник лишней работы — несколько независимых обработчиков lifecycle/realtime, которые одновременно обновляют комнаты, Правила, PUSH и outbox.
- Один сетевой sync сообщений занял 3,58 с одновременно с системным XPC interruption. Кэш уже был показан, поэтому пустой экран из-за этого запроса возникать не должен.
- Нативная активация AppMetrica задержала критический путь запуска на 2056 мс из общего времени 5738 мс (35,7%).

## HTTP-нагрузка

За короткий сеанс зарегистрировано 53 запроса мессенджера.

| Операция | Количество | Оценка |
| --- | ---: | --- |
| `GET /chat/rooms` | 13 | Избыточно: параллельные владельцы синхронизации |
| `GET /chat/contact-aliases` | 7 | Избыточно при частых reconnect/foreground |
| `GET /rules/status` | 6 | Избыточно: запрос выполнялся при смене маршрута |
| `GET /push/preference` | 4 | Избыточно в пределах одного короткого сеанса |
| `PUT /push/registration` | 3 | Повторная регистрация одного и того же устройства |
| `POST .../delivered` | 7 | Realtime и background PUSH подтверждали одни сообщения |
| `GET /chat/messages/:id` | 3 | Ожидаемо: наполнение кэша из background PUSH |
| `POST .../messages/sync` | 4 | Ожидаемо при открытии/возврате в комнаты |
| Остальные | 6 | Авторизация, принятие Правил, участники, read receipt |

Дополнительно выполнено 23 запуска проверки outbox без ожидающих сообщений. Сетевых запросов они не создавали, но вызывали лишние обращения к SQLite и засоряли диагностический журнал.

Десять фоновых HTTP-операций были отменены самим клиентом с сообщением «Фоновый запрос уступил активной операции»: шесть запросов комнат и четыре запроса псевдонимов. Это не серверные ошибки, а следствие запуска фоновой и активной синхронизации почти одновременно.

### Realtime и PUSH

- Два закрытия WebSocket и две ошибки подключения завершились тремя успешными переподключениями — восстановление работает.
- Для входящих сообщений realtime и background notification task конкурировали за одинаковый delivery acknowledgement.
- При открытии комнаты корректно удалено 10 доставленных уведомлений и отправлен один агрегированный read receipt.

## Системные предупреждения

| Сообщение | Количество | Вывод |
| --- | ---: | --- |
| `KSBinaryImageCache ... Binary image cache full` | 187 | Источник — нативный crash reporter; создаёт большой шум и может добавлять работу при старте |
| `Reporter disconnected` | 9 | Совпадает по времени с XPC interruption/crash reporter |
| `kAMAKeychainError -34018` | 2 | AppMetrica Keychain; не привело к потере сессии мессенджера |
| `System gesture gate timed out` | 1 | Единичная задержка системного жеста рядом с XPC interruption; по одному журналу источник не доказан |
| Конфликт ограничений системной клавиатуры | 1 | UIKit/клавиатура, не содержит ограничения приложения |
| StoreKit sandbox error | 4 | Не относится к мессенджеру |
| Предупреждение `UIScene` | 1 | Требование будущей версии iOS/Xcode, не текущая ошибка |
| Deprecation `expo-av` | 1 | Нужна отдельная миграция звуков на `expo-audio` до следующего SDK |

## Исправления в ветке

1. Проверка принятия Правил кэшируется на 5 минут, объединяет параллельные вызовы и повторяется после foreground только по истечении интервала.
2. Синхронизация PUSH-регистрации объединяет параллельные вызовы и не повторяется чаще одного раза в 5 минут. Изменение нативного push-токена выполняет принудительную синхронизацию.
3. Удалён отдельный сетевой запрос комнат из звукового обработчика авторизации. Состояние mute теперь получает владелец SQLite/room sync.
4. Фоновая синхронизация комнат не запускается, когда приложение неактивно; debounce увеличен до 1,5 с, а свежий фоновый snapshot переиспользуется 5 секунд.
5. Delivery acknowledgement объединён в монотонную очередь по комнате: realtime и PUSH больше не отправляют одинаковый sequence дважды.
6. Пустой outbox не проверяется чаще одного раза в 5 секунд и не создаёт запись `flush.finished` без фактической работы.
7. AppMetrica перенесена за границу критического запуска. Аналитические события до активации сохраняются в существующей очереди.
8. React Native-плагин AppMetrica обновлён с 3.6.0 до 4.2.0. Старый podspec жёстко фиксировал нативный SDK iOS 5.16.0; новый допускает актуальную совместимую версию `>=5.16.0 <7.0.0`.

## Ожидаемый эффект

- Убрать повторные `rules/status`, `push/preference` и `push/registration` при быстрых переходах и foreground-событиях.
- Уменьшить количество запросов комнат и отменённых фоновых операций.
- Сократить delivery POST примерно с двух до одного на входящее сообщение в рассматриваемом сценарии.
- Убрать AppMetrica из 35,7% критического пути измеренного запуска.
- Существенно сократить диагностический шум outbox и устаревшего нативного crash reporter.

## Повторная проверка на устройстве

После новой нативной сборки следует записать аналогичный журнал и проверить:

- один `GET /rules/status` при первом входе в мессенджер, без повторов при переходе между комнатами;
- не более одной пары `GET /push/preference` + `PUT /push/registration` на запуск/пятиминутный интервал;
- один delivery POST на входящий sequence;
- отсутствие серии `KSBinaryImageCache ... full` после обновления pod;
- время «Приложение готово» без двухсекундного ожидания аналитики;
- отсутствие `System gesture gate timed out` при открытии/закрытии клавиатуры.
