# Мессенджер Forward Hockey

Статус: архитектура Этапа 0 согласована 9 августа 2026 года.

Этот каталог фиксирует продуктовые границы, модель прав, техническую архитектуру, базовые требования безопасности и черновой контракт API внутреннего мессенджера. Документы являются исходной точкой для серверной и мобильной реализации.

## Принятые основы

- Мессенджер является отдельным модулем приложения Forward Hockey для iOS и Android.
- Сервер мессенджера отделён от сайта WordPress и имеет собственную PostgreSQL-БД.
- WordPress продолжает обслуживать существующие хоккейные данные; сервер мессенджера не читает его БД и не использует WordPress-авторизацию.
- Сервер мессенджера является источником истины для пользователей, ролей, чатов, сообщений, реакций, вложений и приглашений.
- SQLite на устройстве хранит локальный снимок, очередь исходящих действий и состояние синхронизации.
- В первой версии нет личных сообщений, звонков и сквозного шифрования.
- Доступ администратора к содержимому закрытых чатов не является скрытым и всегда журналируется.
- Роли и разрешения хранятся в данных, а не зашиваются в проверки интерфейса.

Подробные решения находятся в [DECISIONS.md](DECISIONS.md).

## Репозитории

- `forward-hockey-app-gcdrwt` — существующее Expo/React Native приложение и общий клиентский контракт.
- `forward-hockey-messenger-server` — отдельный серверный репозиторий, создаваемый на Этапе 1.

Серверный код и секреты не должны размещаться в каталоге `server/wordpress` этого проекта. Общие типы API позднее генерируются из OpenAPI-схемы серверного репозитория.

## Управление изменениями

Изменение ролей, видимости чатов, правил приглашений или модели доступа оформляется сначала в этих документах и покрывается табличными тестами разрешений. Реализация не должна полагаться только на скрытие кнопок: каждое действие повторно проверяется сервером.
